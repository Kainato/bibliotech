# Base do protótipo

## O que eu aprendi

Aprendi que eu ganho muito mais clareza quando defino rapidamente **o que estou construindo** antes de abrir espaço para decidir o visual. O objetivo da primeira etapa não é produzir uma interface bonita; é tirar a ideia da cabeça e transformar o produto em telas, conteúdos e fluxo.

Eu passei a enxergar o protótipo em três camadas:

1. **Objetivo:** qual problema ou tarefa a experiência precisa resolver.
2. **Estrutura:** quais telas existem, que informação cada uma precisa carregar e como o usuário passa de uma para outra.
3. **Interface:** só depois eu trabalho composição, componentes, tipografia, cores e detalhes visuais.

Esse raciocínio reduz retrabalho porque eu consigo descobrir problemas de fluxo antes de gastar tempo refinando pixels.

## Como eu aplico

Antes de montar uma tela no Figma, eu descrevo:

- quem está usando;
- o que essa pessoa quer fazer;
- qual é a principal ação da tela;
- quais informações são necessárias para essa ação;
- para onde o usuário vai depois.

Depois eu monto um esqueleto simples das telas e conecto o fluxo principal.

## Trade-offs & pegadinhas

**Eu não devo começar pelo visual.** Um layout bonito não corrige uma estrutura ruim.

**Eu não devo criar telas só porque parecem necessárias.** Cada tela precisa ter uma função clara no fluxo.

**Eu não preciso resolver tudo no primeiro protótipo.** A primeira versão deve representar o fluxo que eu preciso entender e validar; detalhes secundários podem ficar para depois.
